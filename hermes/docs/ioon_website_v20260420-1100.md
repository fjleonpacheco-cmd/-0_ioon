## 4. Directrices de Diseño de ioon

Existe un archivo `ioon-directrices-diseno_20260411-01.md` que define toda la identidad visual. Resumen clave:

### Principios
- Minimalismo extremo. Tipografía como protagonista. Sin elementos genéricos.
- Editorial, no corporativo. Inspiración: portfolios de arquitectura y galerías de arte.
- Funcional ante todo. Interacciones silenciosas.

### Paleta (6 valores, sin excepciones)
| Token | Hex | Uso |
|-------|-----|-----|
| ink | #0a0a0a | Texto principal, elementos activos |
| paper | #fafafa | Fondo de página |
| muted | #71717a | Texto secundario, labels |
| accent | #18181b | Cuerpo de texto |
| border | #e4e4e7 | Líneas divisorias |
| highlight | #d4d4d8 | Elementos terciarios |

### Tipografía
- **Fuente única:** Space Grotesk (Google Fonts)
- **Peso dominante:** 300 (Light). 400 para labels/UI. 500 solo tabs activos.
- Letter-spacing negativo en headings (-0.5 a -1px), positivo en overlines (2-3px)
- Máximo ancho de párrafo: 680px

### Prohibiciones
- Sin colores fuera de la paleta
- Sin sombras (box-shadow, text-shadow)
- Sin gradientes decorativos (solo overlay oscuro sobre imágenes)
- Sin bordes redondeados > 4px
- Sin animaciones > 0.4s, sin bouncing/scaling/rotating
- Sin emojis, íconos de color, badges con fondo

### Variante Negativo (usada en catálogo)
Los tokens se invierten: ink→#fafafa, paper→#0a0a0a, etc.

## 5. Patrón de Deploy (repetible para cada demo)

### Estructura de carpeta
```
demo-nombre/
├── Dockerfile          ← Multi-stage: Node 20 build + nginx alpine
├── nginx.conf          ← SPA con try_files
├── vite.config.js      ← plugin-react, base: '/'
├── package.json        ← react, react-dom, vite, @vitejs/plugin-react
├── index.html          ← Entry point
└── src/
    ├── main.jsx        ← ReactDOM.createRoot
    └── App.jsx         ← Todo el sitio en un single-file component
```

### Dependencias estándar
```json
{
  "react": "^18.3.1",
  "react-dom": "^18.3.1",
  "@vitejs/plugin-react": "^4.3.1",
  "vite": "^5.4.2"
}
```

### Proceso de deploy
1. Crear carpeta en repo `-0_ioon`
2. Push a GitHub (branch: `main`)
3. En Coolify: New Resource → Public GitHub
   - Repository: `fjleonpacheco-cmd/-0_ioon` (sin https://github.com/, sin .git)
   - Branch: `main`
   - Base Directory: `/nombre-carpeta`
   - Build Pack: Dockerfile
   - Dominio: `https://subdominio.ioon.mx`
4. Deploy

### Nota importante sobre Coolify
- Al crear recurso "Public Repository", Coolify antepone `https://github.com/` automáticamente. Solo poner `user/repo` en el campo Repository, NO la URL completa.
- Wildcard DNS ya está configurado — cualquier subdominio de ioon.mx resuelve al VPS.
- SSL se genera automáticamente (Let's Encrypt) en primer request.

## 9. Lecciones Aprendidas (troubleshooting)

- **Heredocs en terminal macOS:** Copiar todos los archivos de soporte uno por uno, no en bloque. El heredoc del Dockerfile se corta fácil si hay comillas dentro del CMD.
- **Coolify Git Source:** Al crear Public Repository, el campo Repository solo acepta `user/repo`, no URL completa. Si se pone URL completa, duplica el prefijo.
- **Logo en variante negativo:** El logo PNG es blanco sobre fondo negro. No necesita `filter: invert()` en fondo oscuro.
- **Cache del navegador:** Después de redeploy, puede ser necesario hard-refresh (Cmd+Shift+R) para ver cambios.
